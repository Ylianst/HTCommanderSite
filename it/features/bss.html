Supporto del protocollo BSS

Supporto per il protocollo binario proprietario di messaggi brevi di Baofeng / BTech — decodificato tramite reverse engineering e documentato affinché HTCommander possa decodificare messaggi, posizioni e richieste dalle radio di serie.

Due protocolli, un'app

HTCommander parla sia APRS sia BSS. APRS è ben documentato, ma BSS sembra essere un protocollo proprietario non documentato usato dalle radio Baofeng / BTech. HTCommander include un primo tentativo funzionante di decodificarlo, così i messaggi, le posizioni e le richieste dalle radio di serie compaiono insieme a tutto il resto.

Come funziona il formato sul canale

BSS è un semplice protocollo binario codificato in lunghezza, trasportato in un frame AFSK. Inizia sempre con 0x01, il che lo rende facile da distinguere dai frame AX.25. Dopo segue una serie di elementi lunghezza / tipo / dati.

Un pacchetto tipico ha questo aspetto:

0107204B4B37565A540121062468656C6C6F072514C72DC7CDF1

Si decodifica byte per byte come:

01                 // BSS protocol indicator
0720 4B4B37565A54  // Len 0x07, Type 0x20 (From), "KK7VZT"
0121               // Len 0x01, Type 0x21 (To), ""
0624 68656C6C6F    // Len 0x06, Type 0x24 (Message), "hello"
0725 xxxxxxxxxxxx  // Len 0x07, Type 0x25 (Location), Lat + Lng

È un messaggio di testo con una posizione in cui il campo To è vuoto (cosa che accade occasionalmente, anche se di solito è del tutto assente). C'è un'eccezione nella codifica: se il campo lunghezza è 0x85, i due byte successivi sono un contatore di messaggi. Il contatore consente a un ricevitore di ignorare un duplicato dello stesso messaggio, ed è tipicamente usato con richieste come chiedere una posizione o uno squillo.

Tipi di dati noti

TypeNameMeaning
0x20CallsignSource of the message, e.g. N0CALL or N0CALL-0
0x21DestinationMessage destination callsign
0x24MessageA UTF-8 encoded message
0x25LocationSender's position (latitude, longitude, altitude, speed, heading)
0x27LocationRequestRequests the location of a given station
0x28CallRequestRings the requested station, like a phone call
0x85Message counterLength marker followed by a 2-byte counter

A un elemento di posizione (0x25) seguono latitudine e longitudine e, facoltativamente, altitudine, velocità e rotta. Una richiesta di squillo (0x28) fa emettere un bip alla radio di destinazione, un po' come una telefonata in arrivo.

Disponibile su tutte le piattaforme: Windows, macOS, Linux, iOS, Android e web.
