BSS プロトコル対応

Baofeng / BTech の独自ショートメッセージ・バイナリプロトコルへの対応 — リバースエンジニアリングして文書化し、HTCommander が市販無線機からのメッセージ・位置・要求をデコードできるようにしました。

← すべての機能

2 つのプロトコル、1 つのアプリ

HTCommander は APRS と BSS の両方を扱えます。APRS は十分に文書化されていますが、BSS は Baofeng / BTech の無線機が使う、文書化されていない独自プロトコルのようです。HTCommander にはそれをデコードする初期段階ながら動作する実装が含まれており、市販無線機からのメッセージ・位置・要求が他のものと並んで表示されます。

ワイヤーフォーマットの仕組み

BSS は、AFSK フレームで運ばれる、長さでエンコードされた単純なバイナリプロトコルです。常に 0x01 で始まるため、AX.25 フレームと簡単に区別できます。その後に、長さ／種類／データの要素が続きます。

典型的なパケットは次のようになります:

0107204B4B37565A540121062468656C6C6F072514C72DC7CDF1

バイトごとに次のようにデコードされます:

01                 // BSS protocol indicator
0720 4B4B37565A54  // Len 0x07, Type 0x20 (From), "KK7VZT"
0121               // Len 0x01, Type 0x21 (To), ""
0624 68656C6C6F    // Len 0x06, Type 0x24 (Message), "hello"
0725 xxxxxxxxxxxx  // Len 0x07, Type 0x25 (Location), Lat + Lng

これは位置情報付きのテキストメッセージで、To フィールドが空になっています（まれに起こりますが、通常は完全に省略されます）。エンコードには 1 つ例外があります。長さフィールドが 0x85 の場合、続く 2 バイトはメッセージカウンターです。このカウンターにより、受信側は同じメッセージの重複を無視でき、位置やリング（呼び出し）を要求するようなリクエストで通常使われます。

既知のデータ型

TypeNameMeaning
0x20CallsignSource of the message, e.g. N0CALL or N0CALL-0
0x21DestinationMessage destination callsign
0x24MessageA UTF-8 encoded message
0x25LocationSender's position (latitude, longitude, altitude, speed, heading)
0x27LocationRequestRequests the location of a given station
0x28CallRequestRings the requested station, like a phone call
0x85Message counterLength marker followed by a 2-byte counter

位置要素（0x25）の後には緯度と経度が続き、任意で高度・速度・進行方向が付きます。リング要求（0x28）は対象の無線機をビープさせ、着信電話のような動作をします。

すべてのプラットフォームで利用可能：Windows・macOS・Linux・iOS・Android・Web。
