Obsługa protokołu BSS

Obsługa zastrzeżonego binarnego protokołu krótkich wiadomości firmy Baofeng / BTech — poddanego inżynierii wstecznej i udokumentowanego, aby HTCommander mógł dekodować wiadomości, lokalizacje i żądania z fabrycznych radiotelefonów.

Dwa protokoły, jedna aplikacja

HTCommander posługuje się zarówno APRS, jak i BSS. APRS jest dobrze udokumentowany, ale BSS wydaje się być nieudokumentowanym, zastrzeżonym protokołem używanym przez radiotelefony Baofeng / BTech. HTCommander zawiera wczesną, działającą próbę jego dekodowania, dzięki czemu wiadomości, lokalizacje i żądania z fabrycznych radiotelefonów pojawiają się obok wszystkiego innego.

Jak działa format przesyłania

BSS to prosty binarny protokół kodowany długością, przenoszony w ramce AFSK. Zawsze zaczyna się od 0x01, co ułatwia odróżnienie go od ramek AX.25. Następnie występuje seria elementów długość / typ / dane.

Typowy pakiet wygląda tak:

0107204B4B37565A540121062468656C6C6F072514C72DC7CDF1

Dekoduje się bajt po bajcie następująco:

01                 // BSS protocol indicator
0720 4B4B37565A54  // Len 0x07, Type 0x20 (From), "KK7VZT"
0121               // Len 0x01, Type 0x21 (To), ""
0624 68656C6C6F    // Len 0x06, Type 0x24 (Message), "hello"
0725 xxxxxxxxxxxx  // Len 0x07, Type 0x25 (Location), Lat + Lng

To wiadomość tekstowa z lokalizacją, w której pole To jest puste (co zdarza się sporadycznie, choć zwykle jest całkowicie nieobecne). W kodowaniu jest jeden wyjątek: jeśli pole długości to 0x85, kolejne dwa bajty stanowią licznik wiadomości. Licznik pozwala odbiorcy zignorować duplikat tej samej wiadomości i jest zwykle używany z żądaniami, takimi jak prośba o lokalizację lub sygnał dzwonka.

Znane typy danych

TypeNameMeaning
0x20CallsignSource of the message, e.g. N0CALL or N0CALL-0
0x21DestinationMessage destination callsign
0x24MessageA UTF-8 encoded message
0x25LocationSender's position (latitude, longitude, altitude, speed, heading)
0x27LocationRequestRequests the location of a given station
0x28CallRequestRings the requested station, like a phone call
0x85Message counterLength marker followed by a 2-byte counter

Po elemencie lokalizacji (0x25) następują szerokość i długość geograficzna, a opcjonalnie wysokość, prędkość i kurs. Żądanie sygnału (0x28) sprawia, że docelowe radio wydaje sygnał dźwiękowy, trochę jak przychodzące połączenie telefoniczne.

Dostępne na wszystkich platformach: Windows, macOS, Linux, iOS, Android i sieć.
