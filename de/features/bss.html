BSS-Protokoll-Unterstützung

Unterstützung für das proprietäre binäre Kurznachrichtenprotokoll von Baofeng / BTech — rückentwickelt und dokumentiert, damit HTCommander Nachrichten, Standorte und Anfragen von Serienfunkgeräten dekodieren kann.

Zwei Protokolle, eine App

HTCommander spricht sowohl APRS als auch BSS. APRS ist gut dokumentiert, aber BSS scheint ein undokumentiertes proprietäres Protokoll zu sein, das von Baofeng-/BTech-Funkgeräten verwendet wird. HTCommander enthält einen frühen, funktionierenden Ansatz, es zu dekodieren, sodass Nachrichten, Standorte und Anfragen von Serienfunkgeräten neben allem anderen erscheinen.

Wie das Übertragungsformat funktioniert

BSS ist ein einfaches längenkodiertes Binärprotokoll, das in einem AFSK-Frame übertragen wird. Es beginnt immer mit 0x01, wodurch es sich leicht von AX.25-Frames unterscheiden lässt. Danach folgt eine Reihe von Längen-/Typ-/Datenelementen.

Ein typisches Paket sieht so aus:

0107204B4B37565A540121062468656C6C6F072514C72DC7CDF1

Es dekodiert Byte für Byte wie folgt:

01                 // BSS protocol indicator
0720 4B4B37565A54  // Len 0x07, Type 0x20 (From), "KK7VZT"
0121               // Len 0x01, Type 0x21 (To), ""
0624 68656C6C6F    // Len 0x06, Type 0x24 (Message), "hello"
0725 xxxxxxxxxxxx  // Len 0x07, Type 0x25 (Location), Lat + Lng

Das ist eine Textnachricht mit einem Standort, bei der das To-Feld leer ist (was gelegentlich vorkommt, obwohl es normalerweise ganz fehlt). Es gibt eine Ausnahme bei der Kodierung: Ist das Längenfeld 0x85, sind die nächsten zwei Bytes ein Nachrichtenzähler. Der Zähler ermöglicht es einem Empfänger, ein Duplikat derselben Nachricht zu ignorieren, und wird typischerweise mit Anfragen verwendet, etwa der Anforderung eines Standorts oder eines Klingelns.

Bekannte Datentypen

TypeNameMeaning
0x20CallsignSource of the message, e.g. N0CALL or N0CALL-0
0x21DestinationMessage destination callsign
0x24MessageA UTF-8 encoded message
0x25LocationSender's position (latitude, longitude, altitude, speed, heading)
0x27LocationRequestRequests the location of a given station
0x28CallRequestRings the requested station, like a phone call
0x85Message counterLength marker followed by a 2-byte counter

Auf ein Standortelement (0x25) folgen Breiten- und Längengrad und optional Höhe, Geschwindigkeit und Kurs. Eine Klingelanforderung (0x28) lässt das Zielfunkgerät piepen, ein wenig wie ein eingehender Telefonanruf.

Auf allen Plattformen verfügbar: Windows, macOS, Linux, iOS, Android und Web.
