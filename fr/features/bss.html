Prise en charge du protocole BSS

Prise en charge du protocole binaire propriétaire de messages courts de Baofeng / BTech — rétro-conçu et documenté pour que HTCommander puisse décoder les messages, positions et requêtes des radios d'origine.

Deux protocoles, une seule app

HTCommander parle à la fois l'APRS et le BSS. L'APRS est bien documenté, mais le BSS semble être un protocole propriétaire non documenté utilisé par les radios Baofeng / BTech. HTCommander inclut un premier effort fonctionnel pour le décoder, afin que les messages, positions et requêtes des radios d'origine apparaissent aux côtés du reste.

Comment fonctionne le format de trame

Le BSS est un protocole binaire simple encodé en longueur, transporté dans une trame AFSK. Il commence toujours par 0x01, ce qui permet de le distinguer facilement des trames AX.25. Vient ensuite une série d'éléments longueur / type / données.

Un paquet typique ressemble à ceci :

0107204B4B37565A540121062468656C6C6F072514C72DC7CDF1

Il se décode octet par octet comme suit :

01                 // BSS protocol indicator
0720 4B4B37565A54  // Len 0x07, Type 0x20 (From), "KK7VZT"
0121               // Len 0x01, Type 0x21 (To), ""
0624 68656C6C6F    // Len 0x06, Type 0x24 (Message), "hello"
0725 xxxxxxxxxxxx  // Len 0x07, Type 0x25 (Location), Lat + Lng

C'est un message texte avec une position où le champ To est vide (ce qui arrive occasionnellement, bien qu'il soit généralement absent). Il y a une exception dans l'encodage : si le champ de longueur est 0x85, les deux octets suivants forment un compteur de messages. Le compteur permet à un récepteur d'ignorer un doublon du même message, et est généralement utilisé avec des requêtes comme demander une position ou une sonnerie.

Types de données connus

TypeNameMeaning
0x20CallsignSource of the message, e.g. N0CALL or N0CALL-0
0x21DestinationMessage destination callsign
0x24MessageA UTF-8 encoded message
0x25LocationSender's position (latitude, longitude, altitude, speed, heading)
0x27LocationRequestRequests the location of a given station
0x28CallRequestRings the requested station, like a phone call
0x85Message counterLength marker followed by a 2-byte counter

Un élément de position (0x25) est suivi de la latitude et de la longitude, et éventuellement de l'altitude, de la vitesse et du cap. Une requête de sonnerie (0x28) fait biper la radio cible, un peu comme un appel téléphonique entrant.

Disponible sur toutes les plateformes : Windows, macOS, Linux, iOS, Android et web.
